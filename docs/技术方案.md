# AnimeHub 技术方案

## 1. 项目概述

AnimeHub 是一个跨平台动画数据采集与分析框架, 当前聚焦B站平台, 支持追踪目标的声明式管理(CSV)、定时快照采集、增量计算、数据导出(Excel + 图表)。核心设计理念是解耦的分层架构:通过 Repository 模式隔离数据访问, ClientFactory 实现平台无关的客户端创建, 异步 Pipeline 处理数据流转, 为未来多平台扩展提供清晰的扩展点。

## 2. 核心技术选型

| 组件 | 技术方案 | 说明 |
|------|---------|------|
| 语言 | Python 3.12 | 类型提示、async/await 等现代特性 |
| 数据库 | SQLite + SQLAlchemy 2.0 | 轻量、零配置、ORM 完整支持 |
| HTTP客户端 | httpx (AsyncClient) | 异步请求, 连接池管理 |
| 并发 | asyncio + Semaphore | 协程并发, 最大20并发 |
| 限速 | 令牌桶 (RateLimiter) | 替代 time.sleep, 平滑限速 |
| 数据验证 | Pydantic v2 | API 响应验证, 类型安全 |
| 配置 | Pydantic Settings | 支持环境变量覆盖(ANIME_ 前缀) |
| 重试 | tenacity | 指数退避重试(2-30s, 3次) |
| 数据访问 | Repository 模式 | 隔离 ORM 操作, 上层只调用领域方法 |
| 客户端工厂 | ClientFactory | 懒加载注册表, 平台无关的客户端创建 |
| 数据分析 | pandas | DataFrame 计算与导出 |
| Excel导出 | openpyxl (via pandas) | 多 Sheet 报告 |
| 图表生成 | matplotlib | 自动检测系统中文字体 |

## 3. 多平台客户端方案

### 3.1 BaseClient 抽象基类

定义所有平台客户端必须实现的接口契约:

```python
class BaseClient(ABC):
    async def search(keyword: str) -> list[Any]
    async def get_season_info(season_id: int) -> Any | None
    async def get_season_stat(season_id: int) -> Any | None
    async def get_video_stat(aid: int | None, bvid: str | None) -> Any | None
    async def get_video_stats_batch(aids: list[int]) -> list[Any | None]
    async def close()
    async def __aenter__() -> BaseClient
    async def __aexit__(*args)
```

各平台返回的具体类型由子类的 Pydantic 模型定义, Pipeline 按平台分发处理。

### 3.2 ClientFactory 客户端工厂

采用懒加载(Lazy Import)+ 注册表模式:

```python
class ClientFactory:
    _registry = {
        "bilibili": "anime_hub.client.bilibili.client:BilibiliClient",
    }

    @classmethod
    def register(cls, platform: str, import_path: str) -> None
    @classmethod
    def create(cls, platform: str, **kwargs) -> BaseClient
```

- 通过 importlib 动态加载, 不用的平台模块不会被导入
- 新增平台只需一行 `register()` 注册
- 不支持的平台抛出 `ClientFactoryError`

### 3.3 B站 API 方案

#### 3.3.1 番剧搜索 API

```
GET https://api.bilibili.com/x/web-interface/search/all/v2
参数: keyword, search_type=media_bangumi, page, pagesize
```

返回番剧搜索结果, 含 season_id、media_id、评分、集数等。用于 `add` 命令的关键词搜索。

#### 3.3.2 番剧详情 API

```
GET https://api.bilibili.com/pgc/view/web/season
参数: season_id
```

返回完整番剧信息:基本信息、评分、正片集数列表、花絮/特别篇、发布状态。

#### 3.3.3 番剧统计 API

```
GET https://api.bilibili.com/pgc/web/season/stat
参数: season_id
```

返回番剧级汇总统计:views、follow、likes、coins、danmakus、shares。

#### 3.3.4 单集视频统计 API

```
GET https://api.bilibili.com/x/web-interface/view
参数: aid 或 bvid
```

返回单集详细统计(data.stat):view、danmaku、reply、favorite、coin、share、like、his_rank。

#### 3.3.5 API 关键约束

| 约束 | 说明 |
|------|------|
| 无需登录 | 4 个 API 均为公开接口 |
| 频率控制 | 令牌桶限速(默认2.5/s)+ 异步并发(最多20) |
| 重试策略 | tenacity 指数退避, 最多3次(2-30s) |
| 请求头 | 模拟浏览器 User-Agent + Referer |
| 数据时效 | 所有 API 仅返回当前快照, 无历史趋势接口 |

> **重要:** B站不提供历史趋势 API, 所有时序增量数据必须通过定期快照自行计算。

## 5. 采集策略

### 5.1 数据管道:fetch → transform → store

Pipeline 层将采集流程拆分为三个阶段:

```
1. fetch    → ClientFactory.create(platform) → Client 异步获取 API 数据
2. transform → Pydantic 模型 → 按平台分发 → ORM 模型字典
3. store    → Repository 写入数据库
```

每个阶段可独立调用, 也可通过 `crawl_once()` 一步完成。

### 5.2 平台路由

- Orchestrator:通过 `ClientFactory.create(platform)` 获取对应客户端
- Scheduler:每个任务根据 `task.platform` 创建客户端实例
- TrackingTable:根据 CSV 中每行的 `platform` 字段路由
- Pipeline:`crawl_once(season_id, platform)` 接收平台标识

### 5.3 快照设计原则

- **仅追加不覆盖**:每次采集写入新行, 保留完整历史
- **时间戳为关键维度**:captured_at 作为所有增量计算的基准
- **增量的计算公式**:当日增量 = 今日快照 - 昨日快照

### 5.4 采集任务调度

```
CrawlTask 状态流转:

  pending → running → success → (等待 next_crawl_at) → pending → ...
                      ↘ failed → (指数退避) → pending → ...

优先级:
  0 = 在播动画(最频繁采集)
  1 = 普通动画
  2 = 已完结动画(低频采集)
```

### 5.5 追踪表管理

通过 CSV 文件声明式管理追踪目标:

```csv
platform,season_id,title,priority,interval_minutes,paused,tags
bilibili,425,咒术回战 第二季,0,60,false,2024秋;热血
bilibili,39567,葬送的芙莉莲,1,120,false,
bilibili,100332,进击的巨人 最终季,2,1440,true,完结
```

`import` 命令读取 CSV → 同步到 CrawlTask 表 → 按平台路由依次采集。

### 5.6 并发控制

- asyncio.Semaphore 控制最大并发(默认20)
- RateLimiter 令牌桶限速(默认2.5 req/s)
- 失败重试:tenacity 指数退避(2-30s, 3次)
- CrawlTask 失败退避:1min → 2min → 4min → ... → 最多24h

## 6. 分析与导出方案

Analyzer 通过 Repository 访问数据, 不直接使用 SQLAlchemy Session。

## 7. CLI 命令方案

```bash
# 可通过 pip install -e . 安装为系统命令
anime-hub --help

# 或者通过 python -m 调用
python -m anime_hub --help

# 添加动画(关键词搜索 or season_id 直达)
anime-hub add "咒术回战 第二季"
anime-hub add --season-id 425

# 批量导入追踪目标(从 CSV)
anime-hub import
anime-hub import my_list.csv
anime-hub import --dry-run            # 仅校验预览
anime-hub import --skip-crawl         # 只导入不同步采集

# 暂停/恢复采集
anime-hub pause 425
anime-hub resume 39567

# 执行数据采集(可选指定动画或全量)
anime-hub crawl
anime-hub crawl --season-id 425

# 查看已跟踪的动画列表
anime-hub list

# 查看采集任务状态
anime-hub tasks

# 导出报告
anime-hub export --name "咒术回战" --format excel
anime-hub export --name "咒术回战" --format charts
anime-hub export --all --format both

# 查看增量数据
anime-hub diff --name "咒术回战"
anime-hub diff --name "咒术回战" --days 30

# 启动定时调度器
anime-hub schedule
```

## 8. 配置管理

所有配置通过 Pydantic Settings 管理, 支持环境变量覆盖(前缀 `ANIME_`):

```bash
# 覆盖数据库路径
ANIME_DB_PATH=/data/anime.db anime-hub list

# 覆盖追踪文件路径
ANIME_TRACKING_FILE=/data/anime_list.csv anime-hub import

# 覆盖请求间隔
ANIME_REQUEST_DELAY=0.8 anime-hub crawl

# 覆盖日志级别
ANIME_LOG_LEVEL=DEBUG anime-hub crawl

# 覆盖调度检查间隔
ANIME_SCHEDULE_CHECK_SECONDS=300 anime-hub schedule
```

## 9. 已知限制与后续优化方向

| 问题 | 现状 | 优化方向 |
|------|------|---------|
| 仅B站平台 | 其他平台无公开API | 等待平台开放或探索页面解析 |
| 历史趋势数据 | API不提供, 需自行积累快照 | 通过 schedule 命令启动持续采集 |
| Windows终端中文乱码 | 功能正常但显示异常 | 终端编码配置或 Web UI |
| 搜索交互 | 需要交互式输入season_id选择 | Web UI 或 REST API |
| 数据库规模 | 单文件 SQLite | 长期运行考虑定期归档 |
| CrawlTask未过期检测 | 需重启进程才更新下次采集 | 增加运行时动态调整 |
| 单表统计字段B站特有 | coins/his_rank 埋点在模型中 | 新平台时迁移到 JSON extra |
